# Missing evidence and exploratory research

Owner amendment, October 8, 2026: **“lets not block it because evidence is missing.”** This supersedes older automatic missing-evidence execution and delivery gates for exploratory research in this project. Historical receipts, accepted design and scientific verdicts retain their original scope; no missing evidence is retrospectively claimed verified.

Missing original provenance, historical arrival receipts, official-session/action authority or primary-source confirmation must be recorded as **missing/unverified**, with its impact and a stated assumption or proxy where needed. It does not automatically prevent designing, running or delivering a bounded exploratory experiment using usable inputs. Finding more evidence is supporting backlog work; it is not a prerequisite to every experiment.

| Situation | Treatment |
|---|---|
| Prepared data exists; original/request chain unavailable | Use the exact hashed prepared version as an exploratory input; disclose legacy/unverified provenance. Do not label it provider-verified. |
| Historical arrival unknown | Freeze a modeled availability/lag assumption before outcomes; label it modeled. Preserve event/observed/provider clocks separately. |
| Official-session endpoint unverified | State the stored-bar or minute-aggregate proxy precisely. Do not claim an official closing price or observed auction fill. |
| Action/identity coverage incomplete | Declare the price/share basis and affected coverage; preregister missing-data, exclusion and sensitivity handling. Do not claim point-in-time adjustment completeness. |
| Primary rule/source inaccessible | Cite material actually available, label an inferred rule or adaptation explicitly and freeze its formula. Do not claim the original source was read or replicated. |
| A necessary numerical input is absent | Use an explicitly declared defensible proxy, narrower test or missing state. If no usable implementation exists, only that specific operation is blocked. Never fabricate values. |
| Calculation/accounting bug or detected future information | Correct and independently check it before proceeding. An uncertainty label does not make a known error valid. |

Before outcome access, freeze the hypothesis, exact input versions, formulas/units, chronology and availability assumptions, baseline, costs, missing-state handling, metrics, finite trial budget and decision rule. Retain all failed variants. Prior exposed data remains development; protected final access stays disabled unless separately authorized. Old M2's negative/exhausted two-comparison budget remains unchanged; a different new experiment needs its own prospective registration.

Every strategy comparison still retains the frozen scanner alone and the same scanner plus one preregistered stock/market context policy. Qualified clocks may be used where available; otherwise declare modeled clocks and label the resulting inference accordingly. Missing context can remain unknown with a frozen action. Record aligned/conflicting/neutral/unknown states and avoided losses, sacrificed winners and differential costs. Do not choose assumptions or exclusions after seeing losers.

Keep execution readiness separate from evidence confidence: **runnable with assumptions** can coexist with **unverified evidence**. Strict source validators and old qualification ledgers remain truthful; they are not the universal exploratory execution gate. Never turn an unknown field into qualified to get a run admitted. Claims requiring observed fills, original-feed authority, historical availability or independent replication remain unsupported when that evidence is absent.

An exploratory story or release can be accepted with a completed, reproducible result and explicit limitations, including a negative or inconclusive result. Missing corroborating evidence alone must not keep it unfinished. Acceptance must state the actual exploratory scope; do not silently mark an undelivered implementation or an unexecuted experiment Done. Keep the eight tracking stages, agent evidence inspection under the review waiver, relevant independent correctness checks, CI, privacy, exact source/artifact verification and owner commit attribution.

Current execution priority: SR-040's bounded exploratory protocol using available prepared inputs and explicit proxies/assumptions, then its registered small experiment. Source recovery/capture improvements continue as supporting work when they add information. No release assignment, historical verdict, protected holdout, live/brokerage authorization, paid purchase, source-owner job, new session or recurring schedule changes automatically with this amendment.
