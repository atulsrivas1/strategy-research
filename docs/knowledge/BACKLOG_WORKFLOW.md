# Backlog and evidence maintenance

1. Read the scoped brief, index, lessons, handoff, selected plan and live Project. Preserve known unsuccessful families and previously exposed chronology.
2. Select a bounded question by uncertainty resolved, relevance to long-stock/call objectives, dependency-unblocking value and feasible effort/data. Keep ready/blocked/exploratory/deferred/completed distinct from delivery stage.
3. Before outcome access write an exact versioned experiment specification and independent checks. A plan with missing data/splits/criteria is not experiment-ready; complete applicable gates first.
4. Save all executed variants, failures, exclusions, manifests and commands. A bug invalidates affected evidence; a negative result applies to tested scope. An unchanged unsuccessful retry requires an explicit new reason and source/lesson link.
5. After every experiment update the result, scoped lesson, evidence index, dependencies, exposure/trial ledger and handoff; preserve old versions. Rerank affected items and name the next best Ready question. Never convert a favorable proxy result to a fill/call claim automatically.
6. Update issue/Project stage using actual evidence; epics aggregate children and release receipts reconcile scope. No Done until complete documentation, actual separate review, relevant checks, declared publication and exact-artifact verification.

New scope gets a unique numbered story, parent epic, one milestone, mechanism/support, data/dependencies, baseline/budget/decision criteria, information value/effort and named deliverables. Feasibility may conclude defer/no-change; excluded ideas remain visible under M4. No speculative additions to live trading or paid sources.
